# 外设扩展方案（task-V1.04）：温度 + SD NAND 存储 + 双 PDM 麦克风

> 日期：2026-10-01　目标板：nrf54l15dk/nrf54l15/cpuapp（自制板）
> 依据：《元器件引脚及功能模块对应表》、tmp112.pdf、CSNP1GCR01-BOW.pdf、mic 页原理图
> 原则：全部走 Zephyr 现成驱动 + 自检挂钩，失败仅打印不阻断主流程（同 IMU 策略）

## 1. 三器件总览

| 位号 | 器件 | 接口 | 主控引脚 | 电源域 | Zephyr 驱动 |
|---|---|---|---|---|---|
| U2(柔性板) | TMP112AIDRLR | SENS_I2C @0x48 | P1.02/P1.03 | VDD_SENS_3V0 | sensor `ti,tmp112` (CONFIG_TMP112) |
| U12(主板) | CSNP1GCR01-BOW 1Gb SD NAND | SPI(SD 2.0 SPI 模式) | P2.01/02/04/05 | VDD_STORE_3V0_SW | `zephyr,sdhc-spi-slot` + `zephyr,sdmmc-disk` (CONFIG_SDHC+SPI_SDHC+DISK_ACCESS+FATFS) |
| U5/U6(主板) | IM69D128SV01 PDM 麦×2 | PDM 立体声 | CLK=P1.12, DIN=P1.10 | VDD_SENS_3V0 | audio `nordic,nrf-pdm` (CONFIG_AUDIO_DMIC) |

## 2. U2 TMP112A 温度传感器（柔性板，经 FPC）

- I2C 地址：ADD0 接地 → **0x48**（与主板 IMU 0x6B 不冲突，同一 i2c21 总线，400kHz 兼容，器件最高 400kHz 恰好支持）
- ALERT 接地未用 → 只做轮询读温，不接中断
- 温度寄存器 0x00：12bit，0.0625°C/LSB（Zephyr 驱动已处理）
- `zephyr,deferred-init`：VDD_SENS 默认关，驱动不能自动初始化（同 IMU 教训），上电后手动 device_init
- 上电序列：power_domain_set(SENS) → 等 LDO 稳定 → device_init → sensor_sample_fetch/get AMBIENT_TEMP
- **注意**：TMP112 在柔性板上，FPC 未插时扫描不到 0x48 属预期，测试报告"不在位"而非"故障"
- 自检：i2c21 扫描含 0x48 → 读温 → 合理范围判定（-30~85°C 器件工作范围，室内应 15~40°C）

## 3. U12 CSNP1GCR01-BOW SD NAND（128MB）

- 本质是"SD 卡协议 NAND"：SD Spec v2.0，支持 1-bit SPI 模式（板上 SDD1/SDD2 悬空，正是 SPI 模式用法）
- 引脚：SCK=P2.01(经 R27 33Ω) / MOSI=P2.02 / MISO=P2.04 / CS=P2.05(R26 47k 上拉)
- 用 **spi00**（32MHz 高速域，P2 引脚配对；spi20-23 只有 8MHz）。初期 spi-max-frequency 保守 8MHz，稳定后可提 16-24MHz
- 电源：VDD_STORE_3V0_SW 由 PMIC LDO2 控制 → 测试前 power_domain_set(STORE) 并延时 ≥10ms
- 软件栈：`zephyr,sdhc-spi-slot`(spi 子节点) → `zephyr,sdmmc-disk`(disk-name="SD") → DISK_ACCESS → Elm FatFs
- 自检流程：
  1. disk_access_init("SD") → 拿容量（应 ≈ 1Gb=124MB 量级）
  2. 读扇区 0 打印前 16 字节（识别有无 MBR/FAT 引导）
  3. fs_mount FATFS("/SD:")；失败则 fs_mkfs 格式化（**会清卡**，bring-up 阶段可接受）
  4. 写测试文件 → 读回逐字节比对 → 删除 → 卸载
- 掉电安全：产品化后写入前要规划掉电窗口（看门狗 30s 复位场景），本阶段仅 bring-up 验证

## 4. U5/U6 双 IM69D128 PDM 麦克风（立体声）

- 接法（原理图 mic 页）：两麦共享 CLK(P1.12)；DATA 各经 100Ω 汇到同一 DIN(P1.10)；
  **U5 LR select=VDD（右声道/高时隙），U6 LR select=GND（左声道/低时隙）**——标准 PDM 立体声分时隙复用
- IM69D128 时钟范围约 1.0-3.3MHz；16kHz PCM×64 抽取 → PDM CLK=1.024MHz（驱动按 ratio 自动算）
- 用 **pdm20** + Zephyr dmic API：16kHz / 16bit / 2ch，DMA 双缓冲 slab
- 自检流程：
  1. 开 SENS 电源（麦克风同域）→ dmic_configure → dmic_trigger START 采 2 秒
  2. 双声道分离（L=偶数样本，R=奇数样本）→ 各算 RMS 与峰值
  3. 判定：RMS>0（有时钟有数据）；环境安静时 RMS 应很小，拍板/说话时明显增大（交互验证）
  4. 若某声道恒 0 → 对应麦虚焊/LR select 接反（U5/U6 可互换验证）
- 后续（不在本期）：BLE 音频流、Bark/叫声检测、录音存 SD

## 5. 资源与功耗预算

- FLASH 预估增量：TMP112(~1K) + SDHC_SPI+SDMMC+FATFS(~25-35K) + dmic(~4K) ≈ +40KB
  （当前 FLASH 占用 ~5%，余量充足）
- RAM 增量：PDM slab（2×4KB）+ FATFS 工作区(~4K) ≈ +12KB
- 功耗：三域独立电源门控已具备，不测试时保持关闭即可零静态电流（SD standby 150-200µA 也被 LDO2 关断消除）

### 7.2 SD -22 根因（SWD 实测，勿凭猜测）

nrfutil halt 采样 + nrfx 校验函数内埋打印实锤：**nRF54L15 的 spi00 基频是
128MHz**（不是 dtsi 直觉的 32MHz），prescaler 合法范围 **4..126 且必须偶数**
→ SCLK 下限 ≈ **1.016MHz**。SD 规范的 400kHz 初始化时钟在 spi00 上**物理不可达**，
nrfx `spim_frequency_valid_check` 直接 -EINVAL(-22)。

### 7.3 必需的 NCS v3.4.0 本地补丁（SDK 级，重建 NCS 后需重打）

1. `zephyr/subsys/sd/sd.c`（sd_init_io）：`bus_io->clock = SDMMC_CLOCK_400KHZ;`
   → `bus_io->clock = 1015873;`（prescaler=126，唯一贴近 SD 规范的合法频率）
2. `zephyr/drivers/sdhc/sdhc_spi.c`：3 处 `SDMMC_CLOCK_400KHZ` →
   `SDHC_SPI_INIT_CLOCK 1015873`（文件头部加 #define）
3. `zephyr/drivers/spi/spi_nrfx_spim_common.c` 的 resolve_freq **不要动**——
   HAS_PRESCALER 时透传原始频率是对的（曾误改为向下吸附离散频率，反而造出非法 250k）

### 7.4 温度 BLE 通道（本版新增）

- 服务 e5a00010 追加特征值 **e5a00013**（Read+Notify，int16 小端 0.01°C），CCC 在 attrs[8]
- main 主循环 1Hz 读取 TMP112 → `ble_imu_service_notify_temp()`；RTT 每 10s 打 `TEMP,now=x.xx`
- 手机验证路径：连接 → 订阅 e5a00013 → 1Hz 收 2 字节温度；Read 直读最新缓存
- TMP112 未接线时 notify 静默跳过（-ENODEV），不影响其他功能
