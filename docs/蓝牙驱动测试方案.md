> 固件基线：nRF Connect SDK v3.4.0，目标板 `nrf54l15dk/nrf54l15/cpuapp`，控制台 SEGGER RTT
> 参考文档：《Bbo nRF..v1 (3).pdf》§5.1 蓝牙从机（peripheral_lbs 例程）、§5.4 HCI log（本次不涉及）

## 1. 目标与范围

| 项 | 内容 |
|---|---|
| 目标 | 在现有电源 UI 固件上新增 **BLE 从机**功能：手机 nRF Connect App 连接后，通过自定义 GATT 服务控制 **LED0（红）/ LED1（蓝）** 的开关 |
| 硬约束 1 | **不得影响原有 LED 工作逻辑**：开机红闪 / 就绪双闪 / 关机蓝闪 / 按键武装常亮 / 充电红闪 / 心跳指示 / 故障三连闪，全部保持原行为 |
| 硬约束 2 | 不改动 status_led 模块 API（`status_led_set/pulse/blink/init` 原样复用），仲裁在应用层完成 |
| 硬约束 3 | 蓝牙功能用 Kconfig 门控（`CONFIG_APP_BLE_LED_TEST`），量产固件可整体关闭 |
| 不在范围 | OTA/SMP 服务（PDF §5.2）、主模式扫描（§5.3）、HCI log 抓取（§5.4）、BLE 安全配对加密（本次免配对，后续版本再加） |

## 2. 与参考例程（peripheral_lbs）的差异分析

PDF §5.1 使用 NCS 自带 `peripheral_lbs` 例程：`CONFIG_BT_LBS=y` 注册 Nordic LBS 服务，
其写回调**直接操作 SoC GPIO 上的 LED**。本工程不能照搬，原因：

| 项 | peripheral_lbs | 本工程 |
|---|---|---|
| LED 驱动方式 | SoC GPIO 直驱 | **nPM1300 LEDDRV 寄存器（I2C22，经 status_led 模块）** |
| 写回调可否直接点灯 | 可以（gpio_pin_set） | **不行**：I2C 写 + 状态缓存，且与主循环灯效存在并发竞争 |
| 解决 | — | 自定义 GATT 服务；写回调**只置原子标志**，实际点灯由主循环 20ms 周期统一执行（与现有 `pending_events` 消费模式同构，天然避免多线程竞争） |

蓝牙初始化流程与 PDF 一致：`bt_enable()` → GATT 服务注册 → `bt_le_adv_start()`，
连接/断开事件通过 `BT_CONN_CB_DEFINE()` 回调处理。

## 3. 总体设计

### 3.1 蓝牙协议栈配置（prj.conf 增量）

按 PDF §5.1 的最小配置（服务改为自定义）：

```ini
# ---- 蓝牙从机（LED 测试服务）----
CONFIG_BT=y                    # 开启蓝牙功能
CONFIG_BT_PERIPHERAL=y         # 蓝牙为从机角色
CONFIG_BT_DEVICE_NAME="SmartPet"  # 蓝牙广播名称
```

说明：
- nRF54L15 的 BLE controller 直接链接进 cpuapp 应用镜像，无需多核/IPC 额外配置；
- 现有 `CONFIG_SERIAL=n`、RTT 控制台与蓝牙无冲突；
- `app.overlay` 中 HFXO/LFXO 已配置，射频时钟就绪，overlay **无需改动**；
- 不启用配对加密（免配对直写），测试通过后再评估安全需求。

### 3.2 GATT 服务设计（自定义 SmartPet LED 测试服务）

UUID（128-bit 自定义，实现时直接使用）：

| 对象 | UUID | 属性 |
|---|---|---|
| Service | `e5a00001-1e5c-4b8f-9a2d-6c0f7e8d9a0b` | — |
| 特征值：LED Control | `e5a00002-1e5c-4b8f-9a2d-6c0f7e8d9a0b` | Read + Write（带响应） |

**LED Control 协议（1 字节位图）**：

| 写入值 | 含义 |
|---|---|
| 0x00 | LED0、LED1 全灭（override 保持激活） |
| 0x01 | 仅 LED0（红）亮 |
| 0x02 | 仅 LED1（蓝）亮 |
| 0x03 | LED0 + LED1 同亮 |
| 其他 | bit2~bit7 保留，忽略（按低 2 位掩码处理） |

- 读：返回当前 override 显示字节（最后生效值；未激活时返回 0x00）；
- 写：`BT_GATT_WRITE_FLAG` 常规写（带响应），App 界面可看到成功/失败；
- 广播数据：Flags + 128-bit Service UUID（扫到即可辨认）；Scan Response 携带设备名 `SmartPet`；
- 连接参数：默认 `BT_LE_ADV_CONN`（可连接广播）；断开后自动重新广播。

### 3.3 LED 仲裁机制（核心：不影响原有逻辑）

在 `main.c` 的 `update_led_pattern()` 顶部插入一级判断，优先级自上而下：

| 优先级 | 来源 | 行为 | BLE override 状态 |
|---|---|---|---|
| 1（最高） | FAULT 故障 | 三连红闪图案 | 不受影响，系统强制 |
| 2 | 按键武装/关机提示（`button_pressed`） | 1~3s 红常亮 / ≥3s 红蓝同亮 | 保持，但显示被系统抢占 |
| 3 | CHARGE_ONLY（USB 插入） | 1s 周期红闪 | 保持，但显示被系统抢占 |
| 4 | **BLE 测试 override** | 显示 App 写入的字节 | **本层生效** |
| 5（最低） | ACTIVE 心跳/静默 | 原有逻辑 | — |

规则：
- BLE override **仅在 `APP_STATE_ACTIVE` 且无按键按下**时可见（覆盖心跳层）；
- 短按状态确认（蓝灯双闪）为 `handle_events()` 内的阻塞式 pulse，天然优先显示，完毕后下一周期（≤20ms）恢复 override 显示——属预期行为；
- **App 断开连接时 override 自动清除**，LED 立即回落到正常图案（心跳或静默）；蓝牙监督超时（约 5s）可兜底捕获手机异常离场；
- 关机流程（`request_graceful_shutdown()`）入口处主动断开蓝牙连接并停止广播，随后蓝闪 3s → 进 Ship，此时整机断电、广播消失。

### 3.4 线程模型（并发安全）

```
BT RX 线程（GATT 写回调）          主循环（20ms 周期）
        │                                │
        ├─ atomic 写 override 字节 ──►  update_led_pattern()
        │                                ├─ 计算/读取优先级仲裁
BT 线程（断开回调）                   ├─ status_led_set()（唯一 I2C 写点）
        └─ atomic 清除 override ──►     └─ 主循环保留所有原有逻辑
```

- GATT 回调中**只做原子变量读写 + printk**，不做 I2C 操作；
- 所有 LEDDRV 寄存器写仍集中在 `status_led_set()`（主循环 + 初始化阻塞序列），`status_led.c` 零改动；
- 与现有 `pending_events`（PMIC 中断 → 主循环消费）架构完全同构。

### T7 原有 LED 逻辑回归（**核心用例**）

| 子项 | 操作 | 预期（原有行为不变） |
|---|---|---|
| a 开机灯效 | 重新上电 | 开机红闪 3s → 就绪双闪 3s 正常，期间蓝牙在后台起广播（互不干扰） |
| b 短按 | BLE override 点亮红灯状态下，短按 SW1 | 蓝灯双闪状态确认照常出现（override 被暂时抢占），完毕后 ≤20ms 恢复 override 显示 |
| c 武装 | BLE override 激活状态下按住 SW1 1~3s | 红灯常亮（武装提示）优先于 override 显示 |
| d 关机提示 | 按住 ≥3s | 红蓝同亮提示照常；**RTT 打印 `BLE,disconnected` + `BLE,adv_stopped`** |
| e 关机流程 | 松开触发关机 | 蓝闪 3s 正常 → 进 Ship 断电；App 侧连接断开 |
| f 心跳 | override 未激活（连接后未写值或写后断开） | 心跳双灯快闪（每 5s/100ms）照常 |
| g 充电优先 | override 激活（如 0x03）时插入 USB | CHARGE_ONLY 红闪优先显示，override 被抢占；RTT 有 `POWER_EVENT,vbus=present` |

### 首轮上板发现的两个问题（详见 问题跟踪.txt #007/#008）

1. **#007 断开后广播重启失败 rc=-12**：disconnected 回调内同步调
   bt_le_adv_start，控制器资源未释放 → ENOMEM，断开一次即失联，
   只能重启恢复。已修复：K_WORK_DELAYABLE 延迟 20ms + 100ms×5 重试 +
   shutting_down 互斥（ble_led_test_shutdown 先 cancel 工作项）。
2. **#008 RTT 上行缓冲 1KB 过小**：开机+BLE 日志约 1KB，首轮测试
   中段写满，用户成功的 led_write 记录被 NO_BLOCK_SKIP 丢弃。
   已修复：CONFIG_SEGGER_RTT_BUFFER_SIZE_UP=4096。
