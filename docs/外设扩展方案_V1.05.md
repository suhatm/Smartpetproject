## 2. U1 LSM6DSV16XTR 柔性板六轴（body_imu）

### 接口关系
- 与主板 U4@0x6B **共用 SENS_I2C（i2c21，400kHz）**，柔性板 R1 0Ω 到 GND → SA0=0 → 地址 **0x6A**
- INT1→P0.01（IMU_BODY_INT1，经 FPC1 pin8/13），INT2→P1.11（预留，未启用）
- 电源 VDD_SENS_3V0（nPM1300 LDSW1）经 FPC 供到柔性板，与主板传感域同轨——
  `power_domain_set(POWER_DOMAIN_SENS, true)` 幂等共享，本模块不私自下电

### 初始化流程
1. `body_imu_bringup_test()`：SENS 域上电 → 25ms 稳定
2. **裸 I2C** WHO_AM_I（0x0F 期望 0x70）探测——不依赖驱动 ready，
   FPC 未插时 0x6A 无 ACK → 直接判 ABSENT（返回 1，非错误）
3. 在位 → `device_init()`（overlay 配 `zephyr,deferred-init`，同 U4 教训：
   VDD_SENS 默认关，驱动不能上电自举）→ 读一帧六轴验证数据通路

### 连接状态机（硬件未插时系统正常运行的核心）
```
UNKNOWN ─bring-up/reprobe─→ PRESENT（WHO_AM_I=0x70）
   │                          │ 连续 IO 失败 ≥5 次
   └── 无 ACK ──→ ABSENT ←────┘（转 DEGRADED，停发 I2C 防空转）
                    ↑              │ reprobe / 定时重探测
                    └──────────────┘（允许带电插排线恢复）
```
- ABSENT/DEGRADED 下 `body_imu_read_frame()` 直接返回 `-ENODEV`，**不发 I2C 事务**，
  避免排线未接时每次读都在总线上空转超时拖垮主循环
- 数据结构与主板 `imu_frame` 语义对齐：`body_imu_frame{ax/ay/az_mg, gx/gy/gz_dps10}`，
  单位换算与 `imu_stream.c` 同源（int64 定点），两 IMU 数据可直接对比/融合

## 3. QVAR 人体准静态感应（qvar_sensor）

### 关键认知
LSM6DSV16X 片内 AH/QVAR 模拟前端，**每颗芯片提供 1 路差分 QVAR 通道**
（pin2=SDx/AH1/Qvar1 与 pin3=SCx/AH2/Qvar2 为差分对）。因此四电极 = 两颗芯片：

```
电极 AQ1/AQ2 ─(皮肤接触, 10MΩ中点偏置+499Ω+110pF+ESD)→ AQVAR1/AQVAR2 → U1.Qvar1/Qvar2 ＝ QVAR-A
电极 BQ1/BQ2 ─(经FPC排线→ESD→499Ω+110pF)────────────→ BQVAR1/BQVAR2 → U4.Qvar1/Qvar2 ＝ QVAR-B
```

### 寄存器依据（NCS v3.4.0 lsm6dsv16x_reg.h 实锤）
| 寄存器 | 位 | 作用 |
|---|---|---|
| CTRL7 (0x16) | bit7 `ah_qvar_en` | AH/QVAR 链使能 |
| CTRL7 (0x16) | bits[5:4] `ah_qvar_c_zin` | 输入阻抗 2400/730/300/255 MΩ |
| STATUS_REG (0x1E) | bit3 `ah_qvarda` | QVAR 数据就绪 |
| AH_QVAR_OUT_L/H (0x3A/0x3B) | — | 16bit QVAR 原始输出（单差分值） |

### 数据手册强制时序（模块内部自动完成）
置 `ah_qvar_en=1` 之前，**加速度计与陀螺仪必须先 power-down（ODR=0）**，使能后再恢复 ODR。
`qvar_channel_enable()` 内部序列：读存 CTRL1/CTRL2 → ODR 清 0 → CTRL7 read-modify-write
（置 en + zin，保留其他位）→ 恢复 CTRL1/CTRL2。
已 grep 确认 NCS Zephyr 驱动不触碰 CTRL7，裸寄存器配置与驱动 XL/G 通路无冲突。

**上板实锤的两个坑（已在代码注释固化）**：
1. **LSM6DSV16X 的 CTRL1/CTRL2 位布局与 LSM6DSO 等老型号不同**：
   `odr_xl/odr_g` 在**低 4 位**（bit3:0），bit6:4 是 op_mode。误按"高 4 位 ODR"
   操作（掩码 0xF0）会把值写进 op_mode 且 ODR 恒 0——芯片静默无数据。
2. **开机自检阶段 Zephyr 驱动尚未 device_init（deferred-init），保存的 ODR=0**，
   "恢复原值"等于让 XL 继续停摆，而 QVAR 数据率跟随 ODR_XL → ah_qvarda 永不置位。
   修复：恢复阶段检测 ODR=0 时主动给 XL 配 30Hz（`xl_odr_was_powerdown,force_30hz`
   日志）；驱动后续 init 会按 overlay 全量重配，不冲突。

### 通道独立降级
- 通道 → 地址映射：QVAR-A=0x6A（U1 柔性板），QVAR-B=0x6B（U4 主板）
- 某通道所在 IMU 不在位 → 该通道 `QVAR_CH_ABSENT`，读取不发 I2C；
  另一通道的**芯片侧不受影响**
- ⚠️ **更正（2026-10-02，原理图网表复核）**：QVAR-B 芯片在主板 U4，但**电极 BQ1/BQ2 经
  FPC 排线从柔性板引来**（主板页 `[BQ1] FPC1.11` / `[BQ2] FPC1.12`，柔性板页
  `[BQ1] FPC1.10→D5→R30→BQVAR1`）。因此 **FPC 未插时 QVAR-B 电极开路**，输出为悬空
  偏置（上板实测 raw≈-13260）**不是有效信号**，不得判 PASS。
  正确语义：`FPC_ABSENT ⇒ QVAR-B = DEGRADED`（valid 位置 0，不外发数据并上报状态变更）。
  详见 `docs/原理图核对与评审建议.md` P0-1。
- 输入阻抗默认 2.4GΩ（皮肤准静态场景首选），`qvar_channel_enable(ch, zin)` 可调
- 输出 `struct qvar_sample{a_raw,b_raw,a_valid,b_valid}`：per-channel 有效位，
  16bit 原始 LSB，物理量换算（nV/电荷）留待标定阶段按前端增益确定
- `qvar_channel_reprobe()` 支持热插拔恢复

## 4. PVDF 压电信号链（pvdf_adc）

### 硬件链路（原理图 pvdf 页）
```
H2 PVDF膜 ─R12 47k→ U8-CH2 电荷放大(R18 250MΩ∥C34 4.7nF) ─┬─C32 2.2uF→ CH4 高通增益≈-4 →R17 22k→ HEART_AA →R15 1k→ ADC_HEART(P1.05/AIN1)
                                                          └─R19/R20 低通→ CH3 缓冲 →R13 1k→ ADC_RAW(P1.13/AIN6)
R9/R10 分压 → CH1 缓冲 → VBIAS 虚地(≈VDD_ANA/2) →R14 1k→ ADC_REF(P1.14/AIN7)
```

### 电源与初始化
- U8 由 VDD_ANA_3V0（U10 TPS7A2030，EN=ANA_EN=P1.06）供电，复位默认关（R25 100k 下拉）
- **懒初始化**：首次 `pvdf_read()` 才 `power_domain_set(ANALOG)` + `adc_channel_setup`，
  开机自检关闭时（量产省电）不做无谓初始化
- 首次上电等待 1200ms（VBIAS 建立：R9/R10 等效 50k × C24 4.7uF，5τ 保守值），后续读不重等

### ADC 配置（app.overlay `&adc`）
- **nRF54L15 SAADC 与 nRF52 寄存器不兼容**（上板实锤）：gain 枚举为 **2/N 系列**
  （2, 1, 2/3, 2/4, 2/5, 2/6, 2/7, 2/8），内部基准 **0.9V**（非 nRF52 的 0.6V）；
  写 `ADC_GAIN_1_6` 会被驱动拒绝（`Selected ADC gain is not valid`, rc=-22）
- 选型：gain=**2/7** + 内部 0.9V → 满量程 **3.15V**，覆盖 0~3.0V 模拟摆幅；
  12bit → 1LSB ≈ 0.769mV（Zephyr 通用枚举无 ADC_GAIN_2_8，2/7 已是最大可配量程）
- 通道节点必须显式配 `zephyr,vref-mv = <900>`，否则 `adc_raw_to_millivolts_dt`
  换算基准错误
- 三通道：channel@0=AIN1(HEART)，channel@1=AIN6(RAW)，channel@2=AIN7(REF)，
  经 `zephyr,user` 的 `io-channels = <&adc 0>, <&adc 1>, <&adc 2>` 按序绑定
- P1.05 与 uart20 RX 冲突已在 overlay 上方禁用 uart20 规避（双保险），SAADC 独占

### 自检判据
`pvdf_bringup_test()`：连采 4 帧 → **ADC_REF 必须在 1200~1800mV**
（VBIAS=3.0/2 ±20%，运放链路是否活着的直接证据）→ 三路均在 0~3600mV 量程内。
PVDF 膜未接（H2 悬空）不是软件可检测状态——ADC 仍会读到 VBIAS 附近静态值，
由上层应用按信号幅度判活。

### 数据结构
`struct pvdf_sample{heart_mv, raw_mv, ref_mv}`（int32 mV）：
- `heart_mv`：心率信号（高通增益级输出，含 VBIAS 偏置）
- `raw_mv`：低通原始信号（电荷放大直接缓冲）
- `ref_mv`：VBIAS 实测（每帧附带，便于上层做差分去偏置）

## 5. 接口关系与初始化总流程

```
main()
 ├─ power_control_init()                 // 电源域框架（SENS/STORE/ANALOG 三域门控）
 ├─ ...(V1.04 已有自检: IMU/温度/SD/PDM 麦)
 ├─ body_imu_bringup_test()     [4.9]   // SENS 上电 → U1@0x6A WHO_AM_I
 │      │                                 //   ABSENT(返1)→仅告警继续
 │      └─ PRESENT → device_init → 读一帧六轴
 ├─ qvar_bringup_test()         [4.10]  // 对 A(U1@0x6A)/B(U4@0x6B) 两通道：
 │      │                                 //   enable(保存ODR→关XL/G→CTRL7置en+zin→恢复)
 │      │                                 //   → 连读验证 ah_qvarda
 │      └─ 通道所在 IMU 不在位 → 该通道 ABSENT，互不影响
 └─ pvdf_bringup_test()         [4.11]  // ANALOG 上电 → 等 1200ms VBIAS
                                        //   → SAADC 三路 × 4 帧 → VBIAS 窗口校验
```

依赖关系：QVAR-A 依赖 U1 在位（与 body_imu 各自独立探测，互不调对方状态——
解耦考虑：body_imu 驱动未 ready 时 QVAR 裸 I2C 仍可用）；QVAR-B、PVDF 不依赖柔性板
的**芯片可用性**，但 **QVAR-B 的电极经 FPC 引出 → FPC 未插时只能报 DEGRADED**（见上方更正）。

## 6. 软件配置项

| Kconfig | 默认 | 作用 |
|---|---|---|
| `CONFIG_APP_BODY_IMU_TEST` | y | body_imu 模块 + 开机自检 |
| `CONFIG_APP_QVAR_TEST` | y | qvar_sensor 模块 + 开机自检 |
| `CONFIG_APP_PVDF_TEST` | y（depends on ADC） | pvdf_adc 模块 + 开机自检 |
| `CONFIG_ADC` / `CONFIG_ADC_NRFX_SAADC` | y | SAADC 驱动（prj.conf 新增） |

各模块关闭对应 TEST 后编译为 ENOTSUP 桩，不占用资源（量产裁剪路径）。
