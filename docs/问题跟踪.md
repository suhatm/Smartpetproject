## ISS-001 SD NAND 初始化报 -22（spi00 时钟下限）— FIXED

- **日期**：2026-10-01　**分支**：task-V1.04　**状态**：FIXED（依赖 SDK 本地补丁）
- **现象**：`SD_TEST,fail,disk_init_rc=-5/-22`；RTT 报
  `spi_nrfx_spim: Failed to configure nrfx driver: -22` → `sdhc_spi: Card SCLK init sequence failed`。
- **排查过程**：
  1. 先怀疑频率离散校验（`spim_frequency_valid_check`），曾把 Zephyr 侧
     `resolve_freq` 改成向下吸附离散频率 → 250kHz 反而更错（反向坑，已回滚）；
  2. 在 nrfx 校验函数里埋 printk 烧录实测，一次拿到真相：
     `base=128000000 freq=400000 presc=320 max=126 min=2`。
- **根因**：nRF54L15 的 **spi00 基频 = 128MHz**（不是 dtsi `max-frequency=32M` 的直觉），
  prescaler 合法范围 **4..126 且必须偶数** → SCLK 下限 ≈ **1.016MHz**。
  SD 规范的 400kHz 初始化时钟在 spi00 上**物理不可达**，nrfx 直接 -EINVAL(-22)。
- **修复**（NCS v3.4.0 本地补丁，共 4 处，重建 NCS 后需重打）：
  1. `zephyr/subsys/sd/sd.c`（sd_init_io）：`bus_io->clock = SDMMC_CLOCK_400KHZ;` → `1015873`
  2. `zephyr/drivers/sdhc/sdhc_spi.c`：3 处 `SDMMC_CLOCK_400KHZ` → `SDHC_SPI_INIT_CLOCK 1015873`（文件头加 #define）
- **注意**：`spi_nrfx_spim_common.c` 的 `resolve_freq` 在 HAS_PRESCALER 时透传原始频率是**对的**，不要改成吸附离散频率。
- **验证**：`SD_TEST,PASS,cap_mb=120,io=OK`（245760×512B，FATFS 挂载 + 读写比对通过），提交 b24ced6。
- **遗留风险**：1015873Hz 高于 SD 规范初始化上限 400kHz 约 2.5 倍；对本卡（CSNP1GCR01 SD NAND，SPI 模式）实测稳定，换卡时留意首次上电枚举。
- **诊断手法沉淀**：nrfx/驱动层静态分析矛盾时，直接在可疑校验函数里 printk
  实测输入（base/prescaler/min/max），一次烧录胜过十次猜测。

## ISS-002 录完音 IMU/柔性板全灭（recorder 私有 SENS 引用误杀共享轨）— FIXED

- **日期**：2026-10-03　**分支**：task-V1.07　**状态**：FIXED
- **现象**：录音结束后 IMU_U4/QVAR/U1 数据流消失或异常；SENS 域在无人指示下掉电。
- **根因**：`recorder.c` 用**模块私有** `sens_powered` 标志管理 SENS 域：
  `sens_ensure()` 无条件写 LDSW1_SET 并"认领"，录音结束 `sens_release()`
  无条件写 LDSW1_CLR——而 bridge 的 IMU 流 / U1/QVAR/TEMP 基线引用
  （`sens_users` 引用计数）同样依赖该轨，被一并拉闸。
- **修复**：`sens_ensure()` 先读 LDSW 状态寄存器，已导通则不认领
  （不置 `sens_powered`），释放就不会关掉别人的轨。
- **教训**：共享电源轨的引用计数必须单一归属；任何"私有开关标志"
  与共享状态并存都是隐患。

## ISS-003 PWR_SET 关 STORE 后录音/文件操作静默失败（FATFS 状态脱钩）— FIXED

- **日期**：2026-10-03　**分支**：task-V1.07　**状态**：FIXED
- **现象**：上位机关 STORE 域再开，之后 REC_CTRL 返回 OK 但永远收不到
  REC_STATE 事件，上位机"开始录音"按钮永久禁用；REC_LIST 同样失败。
- **根因**：`handle_pwr_set` 直接写 LDSW2_CLR 断电，`sd_store.c` 的
  `mounted` 标志仍为 true、`state` 仍为 PRESENT → `sd_ensure_mounted()`
  直接返回 0 → FATFS 在已断电的卡上操作全部失败；且 `record_run`
  失败路径（sd_rc/open_rc）不发任何事件。
- **修复**：①关 STORE 改走 `sd_unmount()`（卸载+断电+状态复位）；
  ②录音/监听/传输进行中 PWR_SET 关 SENS/STORE 拒绝（ACK -11 BUSY）；
  ③`record_run` 所有失败路径补发 `REC_STATE(0)`，上位机据此复位按钮。
- **教训**：电源域控制必须通知该域上的所有使用方；"先卸载再断电"
  是可移动存储的基本礼仪。

## ISS-004 LED_SET 插 USB 时无反应 + MODULE_STATUS 上报值与实灯不符 — FIXED

- **日期**：2026-10-03　**分支**：task-V1.07　**状态**：FIXED
- **现象**：①插 USB（CHARGE_ONLY 模式）联调时上位机开灯指令 ACK 成功但
  LED 不亮；②上位机 LED 状态灯与板上实灯不一致。
- **根因**：①`update_led_pattern` 的 LED override 只在 ACTIVE 分支生效，
  CHARGE_ONLY 直接返回充电闪烁（方案 §3.3 仲裁原意，但联调场景被当成
  "灯控制坏了"）；②MODULE_STATUS 的 LED 字节直接上报 override 请求值，
  而故障/按键图案优先级更高，请求值≠实际值。
- **修复**：①override 在 CHARGE_ONLY 同样生效（优先级仍低于故障/按键）；
  ②新增 `status_led_get()`，MODULE_STATUS 上报实际生效状态。
- **遗留**：量产若要恢复"充电时禁止 override"， revert ①即可（有注释标记）。
