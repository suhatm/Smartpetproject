## 2. 发现的问题与建议

### P0-1　QVAR-B 电极经 FPC 引出，"FPC 未插时照常工作"是错的 ⚠️

**证据（网表）**：

```
主板 i2c&ble 页： [BQ1] FPC1.11      [BQ2] FPC1.12
柔性板 P1 页：    [BQ1] FPC1.10 →D5→ R30 → BQVAR1 → U4.pin2
                  [BQ2] FPC1.9  →D4→ R29 → BQVAR2 → U4.pin3
```

即 **BQVAR 芯片在主板 U4，但电极 BQ1/BQ2 从柔性板经 FPC 排线引到主板**。

**影响**：
- `docs/外设扩展方案_V1.05.md` 第 54 行已写明"经 FPC 排线"，但第 83 行"FPC 未插时 QVAR-B 照常工作"与第 146 行"QVAR-B 不依赖柔性板"**自相矛盾**，需更正；
- 上板实测 FPC 未插时 `QVAR_TEST,B,PASS,last_raw=-13260` —— 这个值不是有效信号，而是**电极开路后的悬空偏置**，当时判 PASS 属误判。

**建议**：
1. 更正 V1.05 文档表述：QVAR-B 芯片在位、**电极依赖 FPC**；
2. 固件内建立联动：`FPC_ABSENT ⇒ QVAR-B 状态 = DEGRADED`，0x03 帧 valid 位图把 B 位置 0，并上报 EVENT 0x01（原因=电极开路）；
3. 协议/GUI 同步：QVAR-B 面板在 FPC 缺失时灰显并提示"电极开路（柔性板未接入）"，避免上位机把悬空值当数据。

### P0-2　SD 卡没有硬件在位检测脚，状态判定要靠"试挂载"

**证据**：`U12.CD/SDD3#2`（pin2）在 SPI 模式下**必须**用作 CS，被 R26 47kΩ 上拉到 STORE 3V0；`SDD1/SDD2` 悬空 → 没有任何空闲引脚可做卡检测（CD）。

**建议**：
1. 协议明确 SD 状态语义：`挂载成功=PRESENT`、`初始化/挂载失败=ABSENT`、`挂载成功但读写失败=DEGRADED`；SD 状态改为"事件驱动"（上电尝试挂载 + REC/SD 操作失败时立即重判），不做 1Hz 轮询；
2. `SD_TEST(0x0D)` 的 result 增加细分错误码：-1 无卡/初始化失败、-2 挂载失败、-3 写失败、-4 读失败、-5 校验不一致；
3. GUI"在位"灯文案改为"已挂载/未挂载/降级"（demo 已按此语义实现，仅需对标协议措辞）。

### P0-3　LED1（蓝）极性接反属**已知硬件问题**，上位机需提示

已由《电源开关机与LED指示产品方案》§8.1 实锤：`LED2.A → U7.LED1`（PMIC 低边灌流脚），**当前板蓝灯恒不亮**。

**建议**：上位机 LED 面板对 LED1（蓝）加注"⚠ 硬件极性待整改（下一版 PCB / 热风翻转）"，否则调试时会把"点不亮"误判为固件 bug。**不改代码逻辑**，只加提示。

---

### P1-1　麦克风声道语义需在 GUI/协议中写清"单总线立体声"

硬件是 **1 根 CLK + 1 根 DATA**，两麦靠 LR select 引脚分左右（U5=右时隙、U6=左时隙），数据在同一 PDM 流内双沿交织。

**建议**：`REC_CTRL(0x07)` 的 `ch_mask` 语义注明"从同一立体声 PDM 流中保留 L/R 或混音"，GUI 声道标签改为"左麦 U6 / 右麦 U5（共用 PDM 总线）"。

### P1-2　中断线已引到 MCU，建议不要只做盲轮询

可用：`P0.00`(主板 IMU INT1)、`P0.01`(柔性板 IMU INT1)、`P1.04`(主板 INT2)、`P1.11`(柔性板 INT2)、`P0.03`(PMIC_IRQ_N)、`P0.04`(EXT_SYNC_IN)、`P0.02` 空闲。

**建议**：
- IMU 用 **DRDY 中断**触发采样（替代 30Hz 定时轮询），空闲期可进低功耗；
- `PMIC_IRQ_N` 用于 VBUS 插拔/低电**即时**上报（现在靠 2s 轮询 BATTERY 帧，插拔响应慢）；
- `EXT_SYNC_IN` 作为协议待决项 #5「时间同步」的硬件同步入口（多设备同步采集）；
- 上述作为 M3 之后的增强，**不阻塞本期**，但需在协议里预留 EVENT 位（如 VBUS_IN/VBUS_OUT）。

### P1-3　协议 §7.3 待决项，按硬件实测数据给出的取舍建议

| # | 事项 | 建议 | 依据 |
|---|---|---|---|
| 2 | 文件流控 | **加逐 8 块 ACK + offset 断点续传** | 128MB 卡、10s 双声道录音≈320KB，BLE 有效吞吐约 10~20KB/s → 单次上传 20~30s，全量重传代价太高 |
| 3 | 录音格式 | **保留 PCM，不引入 ADPCM** | 存储不是瓶颈（128MB ≈ 35 分钟双声道），瓶颈在 BLE 上传；压缩只会把复杂度换到固件侧 |
| 1 | 实时监听流 | 列为 M4 之后可选（8kHz/8bit 单声道≈8KB/s 可行） | 与录音并存需两套采集路径，本期不做 |
| 5 | 时间同步 | 建议做 `TIME_SYNC`（上位机发 UTC，文件头/列表带时间戳） | 硬件无 RTC 备份电池，只有 EXT_SYNC_IN 可用 |
| 8 | 上位机本地功能 | 优先 CSV 导出 + 波形暂停/游标（回放后置） | 研发调试高频需求 |
| 9 | 帧 CRC8 | 保留 | 1 字节成本，串帧校验/排查好用 |
| 10 | CLI 双模式 | 建议做（M4 顺带），用于上板自动化回归 | 协议库独立后成本很低 |

### P2　可选硬件/设计改进（不影响本期固件）

1. **柔性板在位检测**：`FPC1` 有 4 个 `FPC_RSVD` 空脚，可把其中一个接地、主板侧上拉读取 ⇒ 得到**硬件级 FPC 在位信号**，彻底解决 U1/TEMP/QVAR-B 的"探测式"判定（现在只能靠 I2C 扫不到就判 ABSENT）。
2. **第三路 LED**：nPM1300 `LED2#27` 空置，可加一颗灯做"录音中/存储写入"指示。
3. **SD 的 DAT1/DAT2**（SDD1/SDD2）悬空：若后续想提带宽只能改 4 位 SDIO，但 nRF54L 无 SDIO 外设 ⇒ 维持 SPI 1 位即可，无需改动（确认无遗漏上拉需求）。
4. **QVAR-B 电极走线**：经 FPC 长走线 + ESD 后进 U4，建议实测**串扰/漂移**（A 通道工作时对 B 的影响），必要时在协议里给"基线漂移补偿"字段。
