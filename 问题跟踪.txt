【问题 #001】断 J-Link 的 USB 与断 4 根连接线效果不一样（"拔 J-Link 板子就死"）
--------------------------------------------------------------------------------
状态：待实验最终验证（机理已明确，见下）
发现日期：2026-09-30
现象：
  - 拔掉 J-Link 的 USB 线（4 根杜邦线仍留在板上）→ 板子"死"（无心跳）；
  - 拔掉板侧 4 根杜邦线（J-Link USB 仍插着）→ 板子正常（心跳持续闪）；
  - 逐根拔 SWD 线（单变量实验）→ 每根都不影响运行；
  - 只接电池、完全脱离 J-Link → 板子完全正常。
机理分析（高度怀疑为根因）：
  本机探针为 STM32F072 方案的 OB 克隆 J-Link。断 USB 后探针自身失电，
  其每个 I/O 脚内部的 ESD 保护二极管仍连接到探针自己的 3.3V 电源轨：
    - USB 插着（探针有电）：引脚正常驱动，nRESET 被探针维持高电平 → 板子活；
    - USB 拔掉（探针失电）  ：板子 nRESET（内部 13kΩ 上拉到 3V）的电流经
      探针 ESD 二极管倒灌进失电的探针电源轨，把该轨充到中间电位，
      nRESET 被钳位到约（轨压 + 0.6V），可能低于 SoC 的 VIH →
      芯片被按在复位态 → "板子假死"。
  GND 线仍连接，为寄生电流提供了回路；SWDIO（SoC 内部上拉）同样在
  向失电探针灌电，加剧钳位效应。
待做的决定性实验：
  1. 4 根线全接、USB 插着，确认心跳在闪；
  2. 只拔 J-Link 的 USB 线（板侧 4 根线不动）；
  3. 预期若 20s 内心跳消失 → 机理实锤；重新插回 USB 后应观察到
     "红闪 3s + 双闪 3s" 完整重启序列（芯片从复位态释放后重新 boot）。
规避措施（无论实验结果如何均建议执行）：
  - 调试收工时：先拔板侧 4 根线，再拔探针 USB（顺序不能反）；
  - 或者只断开 RESET 那一根线，探针 USB 可以一直插着；
  - 量产无影响：产品上没有探针，该问题仅限调试场景。
对已有结论的影响：
  - 板子硬件与固件本身零缺陷（纯电池独立运行已验证正常）；
  - 之前"拔 J-Link 就死"的所有观测，均可用本机理解释；
  - 验证记录《上板验证记录-电源UI固件.md》§7 的"结案"结论需要按本问题
    实验结果修订（误判的根因从"Ship 态短按无反应+灯效太短"修正为本机理）。

【问题 #002】nPM1300 OTP 冷启动默认 Active（插电池即开机）——运输耗电风险
--------------------------------------------------------------------------------
状态：待产品决策
发现日期：2026-09-30（实测实锤：插电池不按键，SWD 立即可连、RTT 记录完整 boot）
风险：产品出厂/运输途中插上电池即自动开机，持续耗电。
可选方案：
  a) 出厂前产线工位手动长按关机进 Ship（零改动，靠流程保证）；
  b) 用 nPM PowerUP 修改 OTP，把默认态改为 Ship（硬件层面保证，需烧 OTP）。
备注：当前阶段样机调试期间此行为反而方便（插电池即活）。

【问题 #003】LED2（蓝）原理图网表层面极性存疑（实物正常）
--------------------------------------------------------------------------------
状态：实物已验证正常，原理图层面留档
结论：实板蓝灯可正常点亮（关机蓝闪、短按确认均可见）。网表分析判"接反"
      是符号库（MHT192DBCT pin1=K）与实物引脚定义差异造成的误判。
建议：下一版原理图选型时统一 LED 符号库极性定义，或改用双向/双色管，
      避免 DRC 阶段再次误报。
附带事实：蓝灯 Vf 2.5~3V，Buck1 未使用（VSYS≈VBAT 3.0~4.2V），
      电池电压低于约 3.3V 时蓝灯会变暗——低电量场景"关机蓝闪"可能偏暗，
      后续若需要可换低 Vf（≤2.6V）蓝灯。

【问题 #004】NCS v3.4.0 复用 build 目录增量编译会失败（SDK 层坑）
--------------------------------------------------------------------------------
状态：已明确规避方法
现象：非 pristine 的增量编译（ninja -C build 或 west build 复用目录）触发
      nrf_security 模块 Kconfig malformed 赋值报错中止
      （CONFIG_MBEDTLS_CONFIG_FILE 空值 cache 变量被回喂 Kconfig）。
规避：一律使用 `west build --pristine`（约 13 分钟），增量调试期改用
      ninja 时需注意此坑。

【问题 #005】烧录后 RTT 无输出：旧固件残留的满缓冲区跨复位存活
--------------------------------------------------------------------------------
状态：已明确规避方法
现象：烧新固件后 RTT 读不到新日志（WrOff 卡在 0x3FF）。
根因：.rtt_buff_data 为 NOLOAD 段，旧固件写满的 RTT 控制块跨复位存活；
      SEGGER RTT 惰性初始化检测到合法 ID 就跳过重置，SKIP 模式丢弃新日志。
规避：烧录后用 SWD 清零控制块首字再复位：
      nrfutil device write --address 0x20000470 --value 0 --direct
      然后 nrfutil device reset。
